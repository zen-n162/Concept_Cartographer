これは何?

Concept Cartographer は、散らばった研究資料から「概念地図」を自動で描く QST 社内の AI エージェントです。OneDrive・SharePoint・Teams・手元の PDF から資料を読み取り、そこに登場する概念と概念のつながり (因果・相関・分類など) を抽出して、Novak 流の手描き風マップとして 1 枚にまとめます。

チャットに「今週の研究を概念地図として整理して」と一言入れるだけで、資料収集から描画・検証までが自動で走ります。地図はただの絵ではなく、すべての線に「元の資料のどの文に基づくか」という根拠が付いています。線をクリックすれば逐語引用が読めます。

もうひとつの主役は「ギャップ (空白の島)」です。資料の中でまだ繋がっていない場所・機序が説明されていない場所を候補として描き、研究の「次の一手」を考える材料にします。

できること

🗺 概念地図の生成

チャット 1 行で資料収集 → 抽出 → 描画 → 独立検証まで。Excalidraw の手描き風マップ + SVG 出力。

🔍 3 段階の詳細度

Overview (10-20) / Standard (20-50) / Detailed (50-100 要素)。抽出は最初から Detailed 粒度で取り、概念が目標数に届かなければ資料を 1 件ずつ深掘りして粒度を保証します (指示頼みにしないので毎回同じように分かれます)。切替は再生成なし・待ち時間ほぼゼロ。資料が薄くて三段に分かれないときは、水増しせずその旨を注記します。

✏️ 地図の編集

概念の改名・追加・削除、関係の種類変更など 8 操作。元データは書き換えず、いつでも取り消せます。

🎓 修正からの学習

あなたの直しを用語辞書・除外リスト・因果の上書きとして記憶し、次回の生成に反映。適用内容は必ず表示。

💬 資料への質問

「X と Y の関係は?」「全体像をまとめて」に、過去のセッションを横断して出典つきで回答。

❓ ギャップ検出

構造・言説・因果の 3 型で「まだ分かっていない場所」を候補提示。型別レポートで次の一手も提案。

📊 評価と KPI

地図上のクリック評価が正解データになり、関係の正答率・因果の精度を目標値と突き合わせ。

💰 コスト制御

テストモードで同じ依頼の再実行は LLM 呼び出しゼロ。毎回のトークン使用量も表示。

しくみ — 9 段のパイプライン

→ システム構成図 (どこで何が動き、何が Mac の外へ出るか)

設計の合言葉は「LLM は判断が要るところだけ」。資料を読む・概念を抜く・検証するといった判断は LLM が担い、レイアウト・詳細度の計算・記号への変換は決定的なコード (同じ入力なら必ず同じ結果) が担います。

可変詳細度のからくり

地図はいちばん細かい粒度で 1 回だけ生成し、3 段階ぶんの表示計画を 1 つのファイルに同梱します。コミュニティ検出 (Leiden 法) で概念を「島」にまとめ、重要度 (媒介中心性 + 出現頻度 + 新規性) の高い概念から表示枠に入れ、入り切らない概念は「集約ノード」に畳みます。だから Overview ⇄ Detailed の切替は取り出すだけ — 再計算も LLM もありません。

3 段に分かれるには、そもそも細かい粒度で抜けている必要があります。そこで抽出は最初から Detailed 粒度 (概念 30〜80 個) で行い、上位概念だけでなく手法の構成要素・実験条件・個別の結果・数値指標といった下位概念も 1 つずつ立てます。

ただし「細かく抜いて」と指示するだけでは再現しません (同じ依頼で 64 個のときと 20 個のときがありました)。そこで概念が目標数 (既定 45) に届かないときは、資料を 1 件ずつ巡回して追加抽出します — 1 回の呼び出しで 1 資料だけを対象にし、手元に本文がある資料はその本文を、OneDrive/SharePoint 側の資料は「この 1 件だけ読み直して」と名前で指定します。毎回すでに挙がっている概念の一覧を渡すので重複は増えず、同じ概念が別の資料でも語られていた場合は根拠 (原文の引用) だけが足されます。目標に届いた時点、または 2 資料続けて新しい概念が出なかった時点で止まり、何をどれだけ足したかは資料ごとに結果の内訳へ記録されます。

増やすのは粒度であって、資料に無いものを足すことではありません — 創作禁止と根拠必須は変わりません。資料からこれ以上は取れないと分かったときは水増しせず、詳細度カードに「資料から抽出できる概念が上限です」と小さく添えます (Standard と Detailed が同じ枚数になるのは不具合ではなく、資料が薄いという事実です)。

9 層の知識モデル — 地図の下に積まれているもの

画面に見えるのは 1 枚の地図ですが、その裏では情報が 9 つの層に分けて管理されています。合言葉は「上の層は、必ず下の層に根拠を持つ」— 線や主張をクリックすると、層を降りて最後は必ず原文の逐語引用にたどり着きます。根拠まで降りられないものは、そもそも地図に描かれません。

各層のひとこと説明と実装状況

層ひとことで言うと地図での現れ方実装
L1 原文資料の文そのもの (逐語引用)線・ギャップをクリックすると出る「根拠」実装済
L2 文脈各文の議論的役割 (仮説/方法/結果/結論…)言説ギャップ (「方法の記述が無い」) の判定材料実装済
L3 主張資料が言い切った内容の最小単位 (Nanopub 形式)線の展開に出る「紐づく主張」実装済 (簡易形)
L4 概念地図のノード楕円そのもの実装済
L5 オントロジー概念の種類分け (〜の一種 / 〜の一部)◇ 分類・◧ 構成の線実装済 (最小)
L6 意味関係概念どうしの実質的な関係 (因果・相関・依存…)→ 因果・〜 相関・▷ 時系列の線実装済
L7 論証主張の根拠 (Grounds) と論拠 (Warrant)ギャップの「判断材料」・主張の強さ実装済 (C-G-W のみ)
L8 認識論主張どうしの支持・反駁⚡ 矛盾・⇒ 補強の線 (⚡ はこの層でだけ確定)実装済 (内部反駁のみ)
L9 メタ来歴・信頼度・どの検証を通ったか線の展開に出る「検証: 0.81 (validated)」等実装済 (最小)

線をクリックすると出てくる「機械タグ A/B/C/D」はこの層の写しです — A = L5 (オントロジー)、B = L2 (言説)、C = L6 (意味・因果)、D = L8 (認識論) の 4 層 30 種。画面の記号を 8 種に抑えても、内部のこの情報は失われません。

段階実装の方針: 各層は「価値が実測できたら次を積む」の順で育てています。L3 の完全な Nanopublication 化、L7 の完全形 (裏付け・限定条件・反論可能性)、L8 の外部文献への拡張、L9 の監査画面は次のリリース (R3) の範囲です。

記号の読み方 — 画面は 8 種、内部は 30 種

関係の線は 8 種類の記号で描かれます。内部では 4 層 30 種のタグで意味を保持しており、線をクリックすると根拠の引用・内部タグ・検証スコアが全部見えます (「シンプルに見せるが情報は失わない」原則)。

記号意味表示される条件
→因果証明つきのときだけ。機序・介入・反事実の語彙証拠があり、かつ検証器の合成スコアが 0.75 以上の場合のみ矢印になります。それ以外は 〜 に降格
〜相関統計的な関連。因果を含意しません (裏付け不足の因果候補もここへ)
⚡矛盾主張どうしの反駁 (refutes) が別モデルで確定したときだけ。それ以外の対立は灰色破線の「対立候補」として非断定表示
⇒補強複数の独立した証拠が同じ主張を支持
◇分類 (is-a)「A は B の一種」というオントロジー関係
◧構成 (part-of)「A は B の一部」という部分-全体関係
▷時系列時間的な先行 (因果は別途 → で明示)
?疑問主張への問いかけ (questions)
✦ 破線ギャップ候補「まだ繋がっていない場所」。破線 + 半透明の非断定表示で、あなたが 有用 / 却下 を確定します

信頼の仕組み — なぜこの地図を信じられるのか

  • 全ての線に根拠 — 関係には元資料の逐語引用 (evidence) が必ず付き、クリックで読めます。根拠を辿れない関係は無効。
  • LLM の言い分をそのまま描かない — 因果は 3 点セット (候補 → 語彙証拠 → 別モデルの独立検証) を通ったものだけ。検証に落ちた主張は却下ログに記録され、地図から外れた理由ごと「因果ギャップ」の材料になります。
  • 描いた結果も別モデルが検証 — 描画後にキャンバスの実物と計画を突合し、欠落・ラベル不一致を検査します。
  • 人間が最終権威 — あなたの編集は機械判定より常に優先され、上書きされません。ギャップの確定も人間だけが行います。
  • 黙って直さない — 形式修復・学習の自動適用・降格は、何をしたか必ず実行サマリに表示されます。
  • 読めない図を黙って出さない — 関係ラベルの位置は、ノード・島の見出し・他のラベルを避けて地図全体で一括に決めます (ノードの座標は動かしません)。それでも逃げ場が無いラベルは、文字を縮めたうえで「重なりが残った」と実行サマリに表示します。
AI が生成した回答は必ずしも正確とは限りません。重要な判断の前には、根拠の引用を開いて元資料をご確認ください — そのための「クリックで逐語引用」です。

使い方

Web アプリ (おすすめ)

cd production
./scripts/start_web.sh     # → http://127.0.0.1:8090
  1. ホームのテンプレートを選ぶか、依頼文を入力して送信
  2. 進捗カードで 13 ステージの進み具合を確認 (数分)
  3. 結果カードで地図・ギャップ・評価タブを操作。ヘッダーで詳細度を切替
  4. 右上のアカウントカードをクリックすると Microsoft 365 へのサインイン/サインアウトができます (デバイスコード方式。実体はこの Mac の az CLI セッションで、サインアウトは CLI 側にも効きます)
  5. 線をクリック → 根拠と内部タグ。編集モードで直す → 次回の生成が賢くなる

ウィンドウを細くしても崩れません。幅が足りなくなるとヘッダーの 3 カードは潰れる前に折り返し、さらに狭いとサイドバーは自動で閉じて、開いたときは本文の上に重なるドロワーとして出ます (背景クリックか Esc で閉じます)。広げ直すと元のサイドバー設定に戻ります — 狭い画面で閉じたことを「既定」として覚えたりしません。

コマンドライン

# 地図生成
./.venv/bin/python -m cc_orchestrator.chat "今週の研究を概念地図として整理して"
# 質問 (出典つき回答)
./.venv/bin/python -m cc_orchestrator.chat "SuperPCAとスーパーピクセルの関係は?"
# ギャップの型別レポート
./.venv/bin/python -m cc_orchestrator.chat --gap-report <セッションID>

テスト・検証時の節約

設定のテストモード (CLI は --test-cache) を入れると、同じ依頼 + 同じ設定の再実行は 6 時間以内なら前回結果を再利用します — LLM 呼び出しゼロ・数秒で完了。使用量は毎回表示され、--token-report で日別集計も見られます。

開発の歩み

PoC — チャット 1 行 → 資料収集 → 抽出 → Excalidraw 描画 → 独立検証の実証 (4 エージェント構成、実測 2.5〜3.5 分)
R1 個人モード — 可変詳細度 3 段・因果 3 点セット・ギャップ確定・経路判定・評価収集・ヘッドレス SVG
R1.5 — 地図の編集 8 操作 (原本不変 + 追記ログ) と、修正からの学習。ローカル Web アプリ
R2a 多層化 — 文脈ラベル・簡易 Nanopub 主張・3 検証器・Toulmin 論証・内部矛盾検出・8 記号・ギャップ 3 型
R2b 検索 — セッション横断の索引と QA 3 経路 (出典つき回答・LazyGraphRAG-lite)
R2c 評価・推薦 — 日本語正解セットによるオフライン KPI・型別 Gap Report・閉世界推薦
可読性 v2 — 関係ラベルの重なりを地図全体で一括に解消。キャンバスと SVG が同じ位置に描き、解消できない分は警告として表示

データの扱い

  • 資料の読み取りは 本人権限 (Work IQ 経由)。読めるのはあなたが読めるものだけ
  • 生成物 (知識グラフ・地図・編集履歴・評価) はすべて手元の graphs/ と logs/ に保存。既定で外部サービスへの送信はありません (論文推薦の公開 API は明示的に有効化したときのみ・送信内容は全件記録)
  • 研究内容 (概念名・逐語引用) を含むファイルは GitHub 公開から機械的に除外
この説明は R2c + コスト制御 + 可読性 v2 + 抽出 v2 (資料ごとの追加抽出) + 狭幅レスポンシブ + Web サインイン (2026-08-07) 時点の実装に基づきます。機能追加・仕様変更の際にこのページも更新されます。
